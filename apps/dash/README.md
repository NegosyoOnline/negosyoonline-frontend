# NegosyoOnline dashboard

The subscriber dashboard. Staging is `dash-staging.negosyonline.com` (Vercel project `negosyoonline-dash-staging`, deployed from `main`).

The dashboard is static HTML, CSS and JavaScript in `public/`, moved as is from the TWCinc `negosyoonline-dash` folder. Next.js only serves it: `next.config.ts` supplies the routing, the security headers and the CSP. It signs in against the API with a bearer token and shows only real API data. It holds no secrets.

## Pages

| Path | File | Purpose |
| --- | --- | --- |
| `/` and every dashboard section (`/orders/`, `/account/`, `/settings/billing/`, `/settings/general/`, `/settings/shipping/`, `/earnings/`, ...) | `public/index.html`, `assets/js/dashboard.js` and the per-section scripts | The dashboard. `dashboard.js` routes sections in the browser with the History API. |
| `/verify-email/` | `public/verify-email.html`, `assets/js/verify.js` | Target of the emailed verification link |
| `/social-complete/` | `public/social-complete.html`, `assets/js/social-complete.js` | Finishes a Facebook or Google sign-in |

Shared: `assets/js/app.js` (API client, shell, formatting), `assets/css/dash.css`, `assets/js/theme.js`.

## Routing

- Every path ends in a slash (`trailingSlash`); a path without it redirects to the slash form, query string kept.
- Real files and `/assets/js/config.js` are served first. Every other path serves `index.html`; an unknown path falls back to Overview in the browser.
- Pages are sent with `Cache-Control: no-store`. `/assets/*` is cached for an hour, so `index.html` loads each asset with a `?v=` token: bump the token of every file a release changes.

## Configuration

`/assets/js/config.js` is generated by `src/app/assets/js/config.js/route.ts` from environment variables read at build time (`src/lib/site-env.ts`):

| Variable | Default (staging) |
| --- | --- |
| `SITE_API_BASE` | `https://api-staging.negosyonline.com/v1` |
| `SITE_URL` | `https://www-staging.negosyonline.com` |
| `SITE_DASH_URL` | `https://dash-staging.negosyonline.com` |

The CSP `connect-src` follows `SITE_API_BASE`. Production must set all three. The API must list the dashboard origin in CORS.

The CSP allows images from one public Vercel Blob media host, set as `mediaOrigin` in `next.config.ts`. It must match the backend's public media host.

## Behaviour notes

- The sign-in token lives in `localStorage` (`no_dash_token`). A 401 clears it and sends the visitor to the public site, which opens its sign-in popup (`/?signin=1`). The dashboard has no login page.
- Statuses, dates, amounts and the referral link come from the API; the browser only formats them.

## Temporary staging preview

`public/assets/js/preview.js` exists only until sign-in works against the NegosyoOnline API. On `dash-staging.negosyonline.com` and `localhost` it opens the dashboard with a placeholder account and no data instead of leaving for the public site, and answers every API call itself. On any other host it does nothing. Remove the file and its `<script>` tag in `index.html` when sign-in is ready. It is the only difference between `index.html` and the TWCinc original.
